This document summarizes security and data-handling controls for InfoSec and procurement reviews. It describes the current Lazarus architecture — not a certification claim.

1. Product summary (v1 — shipped)

Lazarus v1 is a deterministic deal autopsy engine for stalled B2B pipeline. Customers upload a sales call recording and/or transcript. A private API server transcribes audio (optional AssemblyAI), runs AI-assisted extraction (Layer 1), deterministic scoring (Layer 2), and returns a deal autopsy report with evidence quotes, People Map, Deal Risk Index (DRI), and recovery recommendations. Humans decide; Lazarus does not send outreach or close deals autonomously.

5. Recording consent

Lazarus does not record calls. Customers upload content and warrant they have legal authority to do so (PIPEDA, U.S. state laws, employment and customer agreements). This is the primary legal risk surface for the product — see Terms §2 and DPA §2.

6. Sub-processors

Same list as Privacy Policy §7. Primary hosting: North America.

7. Incident response

  • Monitor API and database availability and error rates
  • On confirmed personal data breach: notify affected B2B customers without undue delay
  • Contain, investigate, remediate, and document per DPA §7

8. Customer responsibilities

  • Obtain recording consent and internal policy approval
  • Manage user access within their organization
  • Configure retention preferences where available
  • Review AI outputs before acting on them in live deals

9. Roadmap (not yet implemented)

Commonly requested — disclosed honestly in security reviews:

  • SOC 2 Type II — not yet obtained
  • Supabase Auth end-to-end (browser login + user_id on every save)
  • Single sign-on (SAML/OIDC)
  • Formal penetration test report
  • CRM native integrations (Salesforce / HubSpot)
  • White-label partner dashboard and custom domains
  • Continuous stall detection from CRM activity and email (not call-only)
