This document summarizes security and data-handling controls for InfoSec and procurement reviews. It describes the current Lazarus architecture — not a certification claim.

1. Product summary

Lazarus is a B2B deal recovery platform. Customers upload sales call recordings and/or transcripts. A private API server runs AI extraction (Layer 1), deterministic scoring (Layer 2), and stores results in a tenant-isolated database. The web UI is display-only — scoring logic never runs in the browser.

5. Recording consent

Lazarus does not record calls. Customers upload content and warrant they have legal authority to do so (PIPEDA, U.S. state laws, employment and customer agreements). This is the primary legal risk surface for the product — see Terms §2 and DPA §2.

7. Incident response

  • Monitor API and database availability and error rates
  • On confirmed personal data breach: notify affected B2B customers without undue delay
  • Contain, investigate, remediate, and document per DPA §7

8. Customer responsibilities

  • Obtain recording consent and internal policy approval
  • Manage user access within their organization
  • Configure retention preferences where available
  • Review AI outputs before acting on them in live deals
